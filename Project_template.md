# Проектная работа: RAG-бот для QuantumForge Software

## Задание 1. Исследование моделей и инфраструктуры

### 1.1 Сравнение LLM-моделей

#### Локальные модели (Hugging Face)
- **Качество ответов**: Хорошее для базовых задач, но может уступать облачным моделям по сложным запросам
- **Скорость работы**: Зависит от железа, обычно медленнее облачных (особенно без GPU)
- **Стоимость**: Единоразовая (сервер + GPU), нет платы за токены
- **Удобство развёртывания**: Требует настройки инфраструктуры, управления моделями

#### Облачные модели (OpenAI / YandexGPT)
- **Качество ответов**: Отличное, особенно GPT-4
- **Скорость работы**: Быстрая, стабильная
- **Стоимость**: Pay-per-use, может быть дорого при больших объёмах
- **Удобство развёртывания**: Очень простое, только API ключ

**Выбор для кейса**: Для корпоративного использования с конфиденциальными данными лучше локальные модели, но для MVP можно начать с облачных.

### 1.2 Сравнение моделей эмбеддингов

#### Локальные (Sentence-Transformers)
- **Скорость создания индекса**: Зависит от CPU/GPU, приемлемая
- **Качество поиска**: Хорошее для большинства задач
- **Стоимость**: Бесплатно, только вычислительные ресурсы

#### Облачные (OpenAI Embeddings)
- **Скорость создания индекса**: Быстрая, стабильная
- **Качество поиска**: Отличное
- **Стоимость**: $0.0001 за 1K токенов

**Выбор для кейса**: Локальные модели (например, all-MiniLM-L6-v2) — баланс качества и стоимости.

### 1.3 Сравнение векторных БД

#### FAISS
- **Скорость поиска**: Очень быстрая
- **Скорость индексации**: Быстрая
- **Сложность внедрения**: Низкая (встроенная в LangChain)
- **Удобство**: Простое API
- **Стоимость**: Бесплатно

#### ChromaDB
- **Скорость поиска**: Хорошая
- **Скорость индексации**: Хорошая
- **Сложность внедрения**: Средняя (требует отдельного сервиса)
- **Удобство**: Хорошее API, персистентность
- **Стоимость**: Бесплатно, но требует дополнительной инфраструктуры

**Выбор для кейса**: FAISS — для начала проще и достаточно для MVP.

### 1.4 Рекомендуемая конфигурация сервера

**Вариант 1 (Минимальный, для MVP):**
- CPU: 4 ядра
- RAM: 8 GB
- GPU: Не требуется
- Стоимость: ~$50-100/месяц

**Вариант 2 (Рекомендуемый, для продакшена):**
- CPU: 8 ядер
- RAM: 16 GB
- GPU: Опционально (для ускорения эмбеддингов)
- Стоимость: ~$150-300/месяц

**Вариант 3 (Масштабируемый):**
- CPU: 16+ ядер
- RAM: 32+ GB
- GPU: NVIDIA T4 или лучше
- Стоимость: ~$500+/месяц

### Итоговые рекомендации

**Выбранная конфигурация:**
- LLM: Локальная модель (например, Llama 2 7B) или облачная YandexGPT для начала
- Эмбеддинги: sentence-transformers/all-MiniLM-L6-v2 (локальная)
- Векторная БД: FAISS
- Сервер: 8 CPU, 16 GB RAM

**Обоснование**: Баланс между простотой внедрения, стоимостью и производительностью. FAISS достаточно для начала, можно мигрировать на ChromaDB при необходимости масштабирования.

## Задание 3. Создание векторного индекса

### Выбранная модель эмбеддингов

- **Модель**: `sentence-transformers/all-MiniLM-L6-v2`
- **Репозиторий**: https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
- **Размер эмбеддингов**: 384 измерения
- **Тип**: Локальная модель (не требует API ключей)

### Процесс создания индекса

1. **Загрузка документов**: Все `.txt` файлы из `knowledge_base/`
2. **Разбиение на чанки**: 
  - Размер чанка: 1000 символов
  - Перекрытие: 200 символов
  - Используется `RecursiveCharacterTextSplitter`
3. **Генерация эмбеддингов**: Для каждого чанка создается 384-мерный вектор
4. **Создание индекса FAISS**: Сохранение векторов с метаданными

### Метаданные

Для каждого чанка сохраняются:
- `source`: Путь к исходному файлу
- `title`: Заголовок документа
- `filename`: Имя файла

### Результат

- Создан индекс FAISS в директории `faiss_index/`
- Сохранены метаданные в `faiss_index/metadata.json`
- Реализован скрипт `scripts/build_index_simple.py`
- Протестирован поиск по индексу

**Файлы**: `faiss_index/`, `scripts/build_index_simple.py`

## Задание 4. Реализация RAG-бота

### Архитектура

Создан класс `RAGBot` в файле `rag_bot.py`, который реализует:

1. **RAG-пайплайн**:
  - Получение запроса пользователя
  - Преобразование в эмбеддинг
  - Поиск релевантных чанков в FAISS
  - Формирование промпта
  - Генерация ответа

2. **Few-shot prompting**: 
  - Добавлены примеры в промпт
  - Примеры взяты из той же предметной области
  - Формат: Q&A

3. **Chain-of-Thought (CoT)**:
  - System prompt требует пошаговых рассуждений
  - Бот объясняет свои шаги перед ответом
  - Формат: "Шаг 1: ... Шаг 2: ... Ответ: ..."

### Интерфейсы

Создано два варианта использования:

1. **Консольный режим**: `python rag_bot.py`
2. **REST API**: `python app.py` (FastAPI)

### Результат

- Реализован RAG-пайплайн
- Добавлен Few-shot prompting
- Реализован Chain-of-Thought
- Создан консольный интерфейс
- Создан REST API (FastAPI)
- Реализована фильтрация вредоносного контента

**Файлы**: `rag_bot.py`, `app.py`

3. **Удаление системных конструкций**:
